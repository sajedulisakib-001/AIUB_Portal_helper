Tool Validation Errors

Documentation for the validation rules used when adding a new tool to the extension.

1. How Tool Validation Works

When a new tool is added, the extension performs several validation checks before storing the tool metadata.

  1. The tool folder name is validated.
  2. The tool's metadata.json file is loaded.
  3. The metadata structure is validated.
  4. Referenced JavaScript, HTML, and CSS files are checked.
  5. JavaScript files are checked for the required tool() export.
  6. Tool HTML is checked to make sure it does not contain executable <script> tags.
Important: A validation failure causes the tool to be rejected and prevents its metadata from being stored.

2. Tool Folder Name Validation

The folder name entered in the Settings page must represent exactly one valid folder name.

Allowed characters

  • Uppercase letters: A-Z
  • Lowercase letters: a-z
  • Numbers: 0-9
  • Underscore: _
  • Hyphen: -

The validation pattern used by the extension is: 

/^[A-Za-z0-9_-]+$/

Valid examples

  • calculator
  • color_picker
  • json-viewer
  • tool123
  • my_tool-2

Invalid examples

  • my tool — contains a space
  • my/tool — contains /
  • my\tool — contains \
  • ../tool — contains invalid characters
  • tool.json — contains .
  • tool@home — contains @
Validation Error
Invalid folder names are rejected before the tool metadata is loaded.

3. Empty Tool Name

An empty input is not accepted.

Error message
Please enter a tool folder name.

This also applies when the input contains only whitespace because the input is trimmed before validation.

4. Duplicate Tool

A tool cannot be added if its folder name already exists in the configured tools list.

Example
If calculator already exists, attempting to add calculator again will be rejected.

The extension displays: 

"calculator" is already in your tools.

5. Tool Directory Structure

After the folder name passes validation, the extension expects the tool to exist inside the extension's tool directory. 

app/
└── tools/
    └── your-tool/
        ├── metadata.json
        ├── entry.html
        ├── script.js
        └── style.css

The exact filenames depend on the values defined in metadata.json.

6. Metadata Validation

The extension first loads: 

app/tools/<tool-folder>/metadata.json

If the file cannot be loaded or parsed as JSON, the tool is rejected.

Metadata cannot be loaded
The metadata.json file must exist and contain valid JSON.

Metadata object

The parsed metadata must be an object. A missing or invalid metadata object causes validation to fail.

Invalid metadata
The metadata value is missing or is not an object.

7. JavaScript Action Validation

JavaScript validation is performed when: 

metadata.actions.run

is enabled.

7.1 Missing or invalid script property

When actions.run is enabled, the metadata must contain: 

{
  "actions": {
    "run": true,
    "script": "script"
  }
}

The script value must be a string.

Validation fails when
  • actions.script is missing.
  • actions.script is not a string.

7.2 Missing entry

When the run action is enabled, metadata.entry must also exist.

Validation fails when
metadata.entry is missing or evaluates to a false value.

7.3 JavaScript file does not exist

The script path is constructed as: 

app/tools/<tool-folder>/<actions.script>.js

If that file cannot be fetched, validation fails.

7.4 Invalid JavaScript file

The JavaScript file is passed through the extension's validateScript() validation.

Validation fails when
The JavaScript file does not pass validateScript().

7.5 Missing tool() function

The JavaScript module must export a function named tool.

Example: 

export function tool() {
  // Tool implementation
}

The following is invalid: 

export function start() {
  // ...
}
Validation fails when
The imported JavaScript module does not contain tool as a function.

8. Entry HTML Validation

If metadata.entry exists, the extension expects an HTML file at: 

app/tools/<tool-folder>/<metadata.entry>.html

8.1 Invalid entry type

The entry property must be a string.

Validation fails when
metadata.entry exists but is not a string.

8.2 Entry HTML does not exist

If the referenced HTML file cannot be loaded, the tool is rejected.

Example
If metadata contains: 
{
  "entry": "index"
}
the following file must exist: 
app/tools/my-tool/index.html

8.3 Script tags are not allowed

Tool HTML must not contain executable <script> tags.

The validator removes HTML comments before checking for script tags. Therefore, script tags inside comments are ignored.

Allowed

<!--
<script>
  example();
</script>
-->

Not allowed

<script src="tool.js"></script>
<script>
  console.log("Hello");
</script>
Validation fails
A real <script> opening tag is detected outside HTML comments.

9. CSS Action Validation

CSS validation is performed when: 

metadata.actions.css

exists.

9.1 CSS value must be a string

The CSS property must contain a string identifying the CSS file.

Validation fails when
actions.css exists but is not a string.

9.2 CSS file does not exist

The validator expects the file at: 

app/tools/<tool-folder>/<actions.css>.css

If the file cannot be loaded, validation fails.

10. Example of Valid Metadata

A tool using run, entry, and CSS actions can have metadata similar to: 

{
  "name": "Example Tool",
  "entry": "index",
  "actions": {
    "run": true,
    "script": "script",
    "css": "style"
  }
}

With the following files: 

app/
└── tools/
    └── example-tool/
        ├── metadata.json
        ├── index.html
        ├── script.js
        └── style.css

The JavaScript module must also provide: 

export function tool() {
  // Tool code
}
Valid tool: If all referenced files exist and all validation rules pass, the tool metadata can be stored successfully.

11. Validation Error Summary

Validation Failure Condition
Folder name Empty or contains characters other than A-Z, a-z, 0-9, _ or -.
Duplicate tool The same folder name already exists.
Metadata metadata.json cannot be loaded or parsed.
Metadata object Metadata is missing or is not an object.
Run action actions.script is missing or is not a string.
Run entry metadata.entry is missing when run is enabled.
JavaScript file The referenced .js file does not exist.
JavaScript validation The script fails validateScript().
tool() export The JavaScript module does not export tool as a function.
Entry HTML The referenced .html file does not exist.
HTML script tag A real <script> tag exists outside comments.
CSS property actions.css exists but is not a string.
CSS file The referenced .css file does not exist.
Duplicate metadata The tool path already exists in tools-metadata.

12. Before Adding a Tool

  • Use only letters, numbers, _, and - in the folder name.
  • Do not use spaces.
  • Do not use / or \.
  • Make sure the tool does not already exist.
  • Make sure metadata.json exists and contains valid JSON.
  • If actions.run is enabled, provide actions.script.
  • If actions.run is enabled, provide entry.
  • Make sure the referenced JavaScript file exists.
  • Make sure the JavaScript passes validateScript().
  • Export a tool() function from the JavaScript module.
  • Make sure the entry HTML file exists.
  • Do not put executable <script> tags in tool HTML.
  • If CSS is specified, make sure the referenced CSS file exists.
